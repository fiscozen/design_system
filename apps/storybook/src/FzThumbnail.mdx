# FzThumbnail

Shows an image from a URL, cropped into a box you size.

Before this component the design system had no way to render an arbitrary image.
`FzAvatar` is round and owns its sizes; `FzRadioCard` and `FzCheckboxCard` render
an illustration inside a selectable card. `FzThumbnail` generalises that second
pattern so any surface can show a user-uploaded image — a chat attachment, a
document preview, an upload's pre-send thumbnail.

## Features

- Crops with `object-fit: cover`, so the box never distorts the image
- Dimensions come from the caller, as props — nothing is hardwired
- `alt` is **required**, with an explicit `alt=""` for decorative images
- An `overlay` slot for an action, positioned without a class at the call site
- An optional scrim, so an overlaid control stays legible on a light photo
- A placeholder and an `error` event when the URL is broken, keeping the layout intact
- Lazy-loads by default

## Installation

```bash
npm install @fiscozen/thumbnail
```

`@fiscozen/icons` is a peer dependency: the placeholder is an icon.

## Basic Usage

```vue
<script setup>
import { FzThumbnail } from '@fiscozen/thumbnail'
</script>

<template>
  <FzThumbnail src="/receipt.jpg" alt="Scontrino di marzo" width="158px" height="108px" />
</template>
```

## You own the box

`FzThumbnail` declares no width or height. Give it either:

- `width` **and** `height`, or
- one of them plus `aspectRatio`.

With no dimension at all the box takes its container's width and the image's
*natural* aspect ratio — visible, but at a size neither you nor the design chose,
and the one case where a load failure moves the layout. Measured in Chromium, a
600px container and a 400×300 image:

| unsized box | |
|---|---|
| image loads | 600×450 |
| image fails | 600×20 |

The placeholder, unlike an image, has no natural ratio to supply a height with.
So: give the box a dimension.

**Why props and not a class.** The consuming apps forbid `class` outright at the
organism, template and page layers, and `style` anywhere above an atom, so a
class-only sizing contract would make this component unusable exactly where a
page needs it. Deciding it inside the component is the only way the capability
exists for those layers — the same reasoning as `FzNavbar`'s `elevation`. A
Tailwind class still works from a layer that permits one; use one mechanism or
the other, not both.

## Examples

### An action over the image

```vue
<FzThumbnail :src="attachment.url" alt="" width="100%" height="168px" scrim bordered>
  <template #overlay>
    <FzIconButton
      iconName="arrow-down-to-line"
      ariaLabel="Scarica allegato"
      @click="download(attachment)"
    />
  </template>
</FzThumbnail>
```

`overlayPosition="top-end"` moves it to the opposite corner — a remove control on
a pre-send preview, say.

### Falling back when the image is broken

```vue
<script setup>
import { ref } from 'vue'
const broken = ref(false)
</script>

<template>
  <!-- your own file card, for when there is no image to show -->
  <AttachmentFileCard v-if="broken" :attachment="attachment" />
  <FzThumbnail
    v-else
    :src="attachment.url"
    :alt="attachment.name"
    width="100%"
    height="168px"
    @error="broken = true"
  />
</template>
```

Doing nothing is fine too: the placeholder already occupies the same box, so the
layout does not move — as long as the box has a size of its own. In an unsized
box it collapses to the icon, which is the second reason to pass a dimension.

`error` means *the image failed to load*, and only that. An empty `src` shows the
same placeholder without firing anything — the `<img>` never mounted, so there was
nothing to fail. A caller who wants a single "nothing is showing" signal has to
check `!attachment.url` alongside `@error`.

### Only one dimension known

```vue
<FzThumbnail :src="image.url" alt="Anteprima" width="100%" aspectRatio="16 / 9" />
```

## Accessibility

- **`alt` is required by the type.** A decorative image takes an explicit
  `alt=""`, which reaches the DOM as an empty attribute — a _missing_ `alt` makes
  a screen reader announce the URL instead.
- The thumbnail itself is not interactive and is not a tab stop. Anything you put
  in the `overlay` slot is, so give it an accessible name — `ariaLabel` on
  `FzIconButton`.
- **The name survives a load failure.** A native `<img>` whose URL 404s still
  exposes its `alt` to a screen reader — the element is still there, only the
  pixels are missing. Because this component swaps the `<img>` for a placeholder
  div, it re-applies the name as `role="img"` + `aria-label`; otherwise a
  screen-reader user would end up worse off than a sighted one, who at least sees
  the placeholder icon.
- The placeholder still invents nothing. A decorative `alt=""` stays silent when
  it fails, and so does an empty `src` — neither ever named anything.
- A control over a photo has no guaranteed contrast against it. Use `scrim` when
  you overlay one, and remember it is drawn over the image only.
- Pointing `src` at a third-party host lets that host see the request. Pass
  `:imgProps="{ referrerpolicy: 'no-referrer' }"` when the URL is not yours.

      </td>
      <td>

    </tr>
  </tbody>

The scrim lives in this package's stylesheet rather than in a Tailwind utility on
purpose: the design system's colours resolve to `var(--grey-500, …)`, and Tailwind
cannot decompose a `var()` into channels — so `bg-grey-500/20` generates **no rule
at all**, silently. Do not reach for an opacity modifier on a token colour.

The 20% is `opacity` rather than a baked `rgba(89, 97, 103, 0.2)` for the same
reason: an `rgba()` would freeze `--grey-500`'s *fallback*, leaving a retheming
consumer with the scrim as the one grey that did not move. The scrim is an empty
overlay div, so `opacity` has nothing to bleed onto.
